TextGen templates produce output but give you almost no tools to debug WHY the output is wrong.

## The Problem
- **No line numbers** — when generated output has a bug on line 47, there's no way to trace which TextGen node produced that line
- **No breakpoints** — can't pause TextGen execution mid-generation to inspect state
- **No step-through** — can't watch the template expand node by node
- For newcomers, this makes TextGen feel like a black box

## The Workaround: Comments
Adding comments in TextGen output (e.g., `// Generated by Entity.HandleCreate`) is the only way to trace which template section produced which output. Without these comments, debugging requires mentally simulating the template expansion.

## Why This Matters for Onboarding
A new developer modifying TextGen templates has no debugging aids:
1. Change a template node
2. Regenerate
3. If output is wrong, manually compare before/after and try to guess which node caused the issue
4. Repeat

This is why TextGen iterations took 4+ attempts in the early days — each iteration was essentially trial-and-error.

## Research Result: No Hidden Debugging Exists
Confirmed — there is NO TextGen debugger, breakpoints, or line tracing in MPS (as of 2025). Community workarounds:

1. **`System.out.println(...)` inside `${ }` blocks** — the #1 community approach, output appears in MPS Messages console
2. **"Preview Generated Text"** — right-click a root node → shows output inline without file I/O (fastest feedback loop; available in MPS 3.x+, exact version of introduction uncertain)
3. **Extract logic to BaseLanguage static methods** → attach IntelliJ debugger to MPS process → set breakpoints there
4. **Binary search the template** — comment out sections (conditional on `false`) to isolate which block produces bad output

No plugin or extension (including mbeddr/MPS-extensions) adds a TextGen step-debugger. This is a known community gap.
